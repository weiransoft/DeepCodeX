# Design Aesthetics Guidelines

生成前端代码与 UI 界面时的设计美学原则，**拒绝通用 AI slop 美学**。

## 反 AI Slop 红线

- **禁止**通用渐变背景（purple-to-blue、mesh gradients）
- **禁止**装饰性噪点纹理（noise textures）
- **禁止**无意义的浮动动画
- **禁止**千篇一律的卡片布局（3 列等高卡片）
- **禁止**过度使用 emoji 作为图标
- **禁止**缺乏品牌感的默认配色（Tailwind 默认色）

## 视觉层级

- **字体**：限制 4-5 种字号 + 字重组合
- **颜色**：1 个中性基础色 + 最多 2 个强调色
- **间距**：使用 4 的倍数（4/8/12/16/24/32...）
- **背景**：扁平化，避免渐变/噪点/装饰效果

## 设计差异化

- **品牌感**：每个设计应有独特的视觉语言
- **克制**：展示核心内容，解释放在文本中
- **无缝**：用户不应察觉 APP 与 widget 的边界

## 输出要求

- 生成 UI 前先确认设计方向
- 输出代码时附设计决策说明
- 使用语义化 HTML + ARIA 提升可访问性
- 状态处理：使用 skeleton/animate-pulse 占位

## 与 Karpathy 原则的关系

Karpathy 关注"代码质量"，本指南关注"视觉质量"。两者互补：
- Karpathy：最小代码、精准修改、目标驱动
- 本指南：独特设计、克制表达、品牌差异化
