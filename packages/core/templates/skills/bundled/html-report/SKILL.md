# HTML Report Skill

生成自包含、结构化、视觉精致的 HTML 报告。最终交付为单个 HTML 文件 + `assets/` 目录，浏览器直接打开即可阅读，无需服务器或构建工具。ECharts/Mermaid 通过 CDN 引用，不本地包含大型 JS 库。

## 1. 适用场景

**适用**：从主题、大纲、文档或数据生成全新 HTML 报告（研究、白皮书、PRD、数据看板、简历、作品集等）。
**不适用**：幻灯片演示（用 html-deck skill）；纯前端网站/应用开发（用 web-dev skill）。

## 2. 文档工作流

开发前检查 `.deepcodex/docs/` 是否已有该报告的内容规划文档：
- 已存在规划文档 → 直接进入 Step 1 执行
- 缺失 → 在 `.deepcodex/docs/` 创建 `report-plan.md`（含报告类型、受众、章节大纲、视觉资产清单、调色板、字体选择），再执行

规划文档为中间产物，最终交付仅含 HTML 与 `assets/` 目录。

## 3. 工作流（4 步）

**严禁跳过 Step 1-3 直接写 HTML。**

### Step 1: 需求分析
明确报告的：类型（研究/白皮书/PRD/数据看板等）、受众、语言、核心论点、章节结构（H2 章节 / H3 小节 / H4 子节）。规则：
- 每段只表达一个核心观点，无法一句话概括则拆分
- 通读全部章节标题应能讲完整故事
- 论点必须有数据、示例或逻辑推理支撑

### Step 2: 结构设计
确定调色板（CSS 变量）、字体、布局（最大宽度、栏目结构）、组件样式（标题/引用/卡片/表格/分隔线）。所有颜色通过 CSS 变量定义，禁止字面色。详细规则见 `references/styling-rules.md`。

### Step 3: 内容编写
按章节编写正文内容。规则：
- 语言一致性：整份报告使用与用户输入相同的语言
- 结构化：H2 章节 / H3 小节 / H4 子节
- 重点强调：整份报告统一用 `<strong>` 加粗 或 `<mark class="key">` 主题色高亮，二选一不可混用
- 引用：证据来源用 `<sup><a href="#cite-N">[N]</a></sup>` 上标链接，文末 `<footer><div class="sources">` 列出来源

### Step 4: 样式应用与图表嵌入
1. 脚手架：`bash ./scripts/new-report.sh <name> <output-dir>`，生成 `<name>/` 目录含 `<name>.html` + `assets/`
2. 从 `templates/report-template.html` 选取版式，复制 `<section>` 块替换示例数据
3. 数据图表：ECharts 通过 CDN 引用，初始化逻辑写入 `assets/charts.js` 外部文件
4. 结构图表：Mermaid 通过 CDN 引用，图源写在 `<pre class="mermaid">` 块中
5. 图片：放入 `assets/`，用相对路径引用，命名 `assets/{name}_{w}x{h}.png`
6. 主题色由 CSS 变量驱动，图表色从 `getComputedStyle` 读取

**每个 HTML 文件首行必须为 `<!-- Generated by DeepCodeX -->`。**

## 4. 图表标准

- **数据图表**：柱状、折线、饼图、雷达、热力、散点、桑基等量化图表必须用 ECharts
- **结构图表**：流程图、时序图、组件图等用 Mermaid
- **ECharts CDN**：`<script src="https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js"></script>`
- **Mermaid CDN**：`<script src="https://cdn.jsdelivr.net/npm/mermaid@10/dist/mermaid.min.js"></script>`
- **初始化**：`echarts.init(el, null, { renderer: 'svg' })`，`animation: false`（报告为静态文档）
- **配色**：从 CSS 变量派生，禁止硬编码 hex，禁止默认调色板
- **标题**：每个图表必须有 `<figcaption>` 标题
- **resize**：每个图表实例需绑定 `window.addEventListener('resize', () => chart.resize())`

详细配置见 `references/charting-standards.md` 与 `references/diagram-practices.md`。

## 5. 安全规则

- **禁止内联脚本代码块**：所有自定义 JS 必须为外部文件（`./assets/charts.js`），HTML 内不含 `<script>...</script>` 内联代码（CDN 引用的 `<script src>` 标签除外）
- **CSP 兼容**：HTML 不含 `javascript:` 协议、`eval`、`Function` 构造器、内联事件处理器（`onclick` 等）
- **资源引用**：大型 JS 库（echarts/mermaid）通过 CDN `<script src>` 引用，不本地包含；图片用相对路径
- **链接安全**：外链加 `target="_blank" rel="noopener"`

## 6. 编写规则

- **始终从模板开始**，不从零编写
- **使用 CSS 变量不用字面色**：`color: var(--ink)` ✓，`color: #111` ✗
- **响应式**：最大宽度容器居中，移动端表格横向滚动，网格布局自适应折叠
- **打印友好**：`@media print` 隐藏交互元素，章节边界分页
- **可访问性**：对比度 ≥ 4.5:1（WCAG AA），正文 ≥ 14px，图注 ≥ 12px
- **输出语言跟随用户输入语言**

## 7. 验证清单

交付前确认：
- [ ] HTML 首行为 `<!-- Generated by DeepCodeX -->`
- [ ] ECharts/Mermaid CDN `<script src>` 标签已引入（按需）
- [ ] 图表初始化逻辑在 `assets/charts.js`，无内联 `<script>` 代码块
- [ ] 所有颜色来自 CSS 变量，无硬编码 hex
- [ ] 每个图表/图均有 `<figcaption>` 标题
- [ ] 图片路径正确（`assets/{name}_{w}x{h}.png`）
- [ ] 引用链接（`#cite-N`）与文末来源列表一一对应
- [ ] 移动端表格可横向滚动，网格布局已折叠
- [ ] 对比度 ≥ 4.5:1，正文 ≥ 14px
