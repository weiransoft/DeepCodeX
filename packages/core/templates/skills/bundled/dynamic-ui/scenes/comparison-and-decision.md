# Comparison & Decision（对比与决策场景）

共享契约：依次应用 `SKILL.md`、本场景文件、`templates/manifest.json`、所选 `templates/<id>/template.md`（若存在）与 `tokens/visual-tokens.md`。

## 何时进入本场景

用户意图涉及以下**决策导向**需求：选项对比（A vs B vs C）、技术选型（框架/工具/库间选择）、风险摘要（风险等级 + 影响 + 缓解矩阵）、决策矩阵（多维加权评分）、优劣分析（优缺点并排）。

典型触发词：compare、selection、which is better、difference、recommend、trade-off、对比、选型、决策矩阵、优缺点。

## 何时拒绝

以下情况改用 Markdown 文本回答：
- 仅 1 个选项（无可对比对象）
- 对比维度 ≤ 1（一句话即可说明差异）
- 用户要详细讨论而非摘要式对比
- 无法给出明确推荐或差异化焦点（所有选项在所有维度上基本相同）
- 选项 > 4 或维度 > 7（信息密度过高 — Markdown 表格更合适）

## 强制工作流

1. 确认紧凑可视化比 Markdown 表格更清晰
2. 识别对比形状：矩阵、卡片或优劣
3. 查阅 `manifest.json` 中可提供结构或块样式的就绪模板
4. 边界合适时用就绪模板作骨架；否则选择降级原语
5. 自定义输出选择 `decision-cards` 或 `compact-table-visual`，保持推荐、权衡、中性表面、字体、间距、圆角与焦点规则
6. 无推荐或无有意义的差异化时不渲染 widget

### 布局范式

**决策矩阵**：适用于 ≥3 维度 × ≥3 选项
- 行 = 对比维度，列 = 选项
- 单元格用简洁标记（图标 + 短文本），无长段落
- 推荐选项列用 brand `border-left` 或 brand 头部高亮

**决策卡片**：适用于 2–4 选项 × 3–5 维度
- 每选项一张独立卡片，水平排列
- 每卡列出共享维度作为分隔线行
- 推荐选项默认用徽章/文字提示；悬停/聚焦可强调任何被检视卡
- 用户要产品/来源/供应商/方案/框架/解决方案对比卡时从 `templates/comparison-cards` 起
- 行内容扁平：标签 + 右对齐值或紧凑条，无嵌套行卡
- 每张选项卡遵循卡片信息层级：标题用 `--text-title`、行值用 `--text-body` 或 `--text-code`、行标签/标签用 `--text-caption`，无超 `--text-title` 的数值头条

**优劣布局**：适用于仅 2 选项的二选一
- 左/右或上/下分割
- 正面项仅当含义明确时用 `--success` 或 `--brand` 标记；负面/权衡项用 `--warning`、`--danger` 或 `--text-muted` 标记

### 信息密度约束
- 选项数 2–4（超出则筛至最具代表性）
- 对比维度 3–5（超出则分核心与次要维度）
- 每格文本 ≤15 词或 1 图标 + 关键词
- 维度可量化时用小条 + 值标签；定性维度保持文字
- 标签仅为摘要提示：每选项至多 1-2 个

### 推荐与焦点
- **必须有明确推荐**或**差异化焦点** — 所有选项均等且无推荐可能时不进入本场景
- 推荐选项默认用 brand 文字/徽章强调；卡片边框强调保留给悬停/聚焦或显式选择
- 非推荐选项保持中性表面
- 不渲染默认选中卡；推荐是徽章/文字提示，悬停/聚焦提供检视态强调
- 不在矩阵/卡片下方加推荐理由或结论文本；理由放周边回答

### 权衡呈现
- 不只显示优点（pros）— 必须也显示权衡/缺点
- 图标可区分：勾（优点）/ 警告三角（权衡）/ 中性点（中性）
- 避免单方面呈现

### 样式规范
- 卡/单元格背景：中性表面（`--surface` 或 `--surface-muted`）
- 推荐标记：`--brand` 边框或徽章
- 文本层级：标题用 `--text-title` + 中等字重；内容用 `--text-body` 基线；注释用 `--text-caption` + 弱化色
- 指标层级：行值用 `--text-body` 或 `--text-code`；KPI 优先对比可每选项用一个 `--text-title` 数值强调，非每个值
- 标签简短：维度名 2–5 词，选项标题 6–10 词
- 圆角：选项卡用 `--radius-card`；单元格、标签、紧凑控件用 `--radius`
- 间距：用 `--spacer-*` token 处理卡片内边距、行间距、网格间距、标签、图例、紧凑控件
- 内部行优先用分隔线、条与 token 化间距，再加容器

### 响应式
- 2 选项：并排（flex-row）
- 3–4 选项：窄视口自动换行（flex-wrap）或改垂直堆叠
- 矩阵布局用 `min-width` 网格防列过窄
- 卡片布局用 `minmax(0, 1fr)` 网格，窄视口改垂直堆叠

### 决策静默预检
- 仅当有 2–4 选项与 3–5 有意义维度时用本场景
- 先选布局：矩阵、卡片或优劣
- 着色前标记一个推荐或一个关键差异化维度
- 同时显示优点与权衡；避免单方面对比
- 单元格文本 ≤15 词，用响应式换行/堆叠
- 验证每张卡标题、元数据、行标签、行值、标签、徽章、可选指标用 `tokens/visual-tokens.md` 的卡片信息层级
- 不在视觉下方加理由或结论文本

## 组合指南

1. **评估选项 × 维度**：决定用矩阵、卡片还是优劣布局
2. **定推荐/焦点**：先明确推荐哪个选项或哪个维度是关键差异化
3. **搭骨架**：矩阵 → `<table>` 或 CSS Grid；卡片 → `<div>` flex 容器；优劣 → 两列 flex/grid
4. **填内容**：每格用图标 + 关键词，≤15 词
5. **加强调**：推荐选项加 brand 边框/徽章；关键差异化维度加粗/高亮
6. **UI 外放理由**：推荐摘要与理由放回答文本，不在图下方
7. **降级纪律**：自定义决策视觉必须用 `decision-cards` 或 `compact-table-visual`；不引入定价页卡片、英雄区、彩色状态卡填充、非 token 字号、非 token 间距或自定义圆角值
