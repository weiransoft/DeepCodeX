# Architecture & Flow（架构与流程场景）

共享契约：依次应用 `SKILL.md`、本场景文件、`templates/manifest.json`、所选 `templates/<id>/template.md`（若存在）与 `tokens/visual-tokens.md`。

## 何时进入本场景

用户意图涉及可视化以下**结构关系**：模块关系（组件组织与依赖）、依赖图（包/服务/类间引用方向）、流程图（业务流程、算法步骤、决策分支）、状态迁移（状态机、生命周期变更）、调用链（跨服务请求传播路径）、排期进度（任务时间线、甘特图）。

典型触发词：架构图、流程图、依赖图、调用链、状态机、甘特图、时间线、flow、diagram。

## 何时拒绝

以下情况改用 Markdown 文本回答：
- 节点 ≤ 2 且单一关系（一句话即可）
- 纯线性列表无分支或并行（Markdown 有序列表更清晰）
- 用户要代码实现而非可视化表示
- 关系过于复杂（>20 节点）使单屏不可读 — 建议分层或交互方式
- 图表会需要微小文字、隐藏溢出、重叠标签、连接线穿过文字，或一个内联 widget 含超 2 个无关子流
- 来源关系为稠密多对多图且精确拓扑比解释更重要 — 先摘要或用表/列表

## 生成原则

- **可读性优先于完整性**：解释焦点关系的小图优于需要 cramped 节点或缠结连接线的完整图
- 把每个节点、标签、连接线标签、徽章、图例、相位标记、边界视为真实方框再绘制；放不下则先缩减范围
- 禁止用视觉技巧掩盖布局失败：无微小文字、无裁切溢出、无连接线碰撞上的白色矩形、无压在描边上的标签、无装饰性连接点
- 用结构层级而非密度：将相关模块归入一个边界，展示关键路径，次级依赖移至回答文本或紧凑关系列表

## 强制工作流

1. 确认内联可视化比 Markdown 更清晰
2. 识别关系类型：层级、组件图、流程、状态迁移、调用链或排期
3. 制定适配预算：可见节点、连接线、连接线标签、图例、边界与外部输入/输出
4. 查阅 `manifest.json` 中 `architecture-and-flow` 模板
5. 边界合适时用 `sequence-diagram`、`tree-flow`、`architecture-elements` 或 `gantt-chart`
6. 仅当模板边界不匹配、关系超出其规模或 Markdown 更清晰时否决就绪模板
7. 无就绪模板匹配时选择降级原语 `node-flow` 或 `explanation-panel`，再应用下方 SVG 布局规则
8. 写 SVG 前选择一种骨架：水平流、垂直流、泳道/时序、分组架构或排期；除非各有独立面板否则不混骨架
9. 着色前应用颜色优先级：先中性结构，再 `--brand` 主路径，再 `--chart-series-*` 显式同辈类别；语义色仅用于显式状态/风险/健康图
10. 应用 `tokens/visual-tokens.md` 的字体、间距、圆角 token 后再加场景特定几何；不发明本地字号、行高、内边距、间距或圆角值
11. 若节点数/标签长度/连接线数无法无重叠容纳，分组、拆分、转表/列表或改 Markdown，而非缩小文字、压缩间距、裁切溢出或加装饰色

### 硬可读性门槛

- 自定义架构/框架图保持 ≤6 个未分组模块、≤8 连接线/面板；更大系统用分组边界
- 流程图展示 3-5 主步骤；更多步骤须分组、垂直堆叠或多面板
- 时序图展示 3-5 参与者、4-8 条有序消息；更大协议须分相或拆分
- 一个面板必须有一个焦点路径/组件/相位边界/风险；若一切同等重要，绘制前先选焦点
- 标签须在 token 字号下容纳；缩短标签或将细节移至回答文本，不缩小字号迁就长标签
- 图例、相位标记、侧注计入布局预算，路由连接线前为其预留空间

### SVG 画布规范
- 首选 `viewBox="0 0 720 H"`（H 依内容计算），设 `width="100%"` + `height="auto"`
- 安全区 ≥ 40 设计单位或 viewBox 宽的 6%（取大者）
- 不用固定像素宽度；确保响应式缩放
- `H` 从最低可见对象 + 底部内边距计算；不裁切、不裁剪、不留无法解释的空白

### 文本与节点宽度

| 用途 | 字号 | 估算宽度 |
|---|---|---|
| 标签/标题 | 14px | ~8px/字符 |
| 元数据/注释 | 12px | ~7px/字符 |

节点宽度：`max(标题字符数 × 8, 副标题字符数 × 7) + 24`

不得为强行塞入而降低标签/元数据字号。中文/混排/代码串/数学符号/长标识符先缩短标签或把节点宽度估算增加 30-50%。

### 流程图规则
- 主路径 3–5 步，单一方向（水平或垂直，不混用）
- 节点间距 ≥ 60px；流程节点用圆角矩形（rx=8）；决策节点用柔化菱形；起止节点用胶囊形
- 输出前内部按层/行分配坐标；先算总行宽，超安全宽则换行/堆叠/拆分
- 连接线与标签分轨；连接线标签在线条上下方，绝不在描带正中
- 步骤需标题+详情时用 ≥56px 高的双行节点，而非在箭头旁加文字
- 分支决策每分支预留一条清晰出轨；分支标签碰撞时移入目标节点副标题或拆第二面板

### 时序与状态流规则
- 双向流（如 TCP 握手）优先泳道/生命线：参与者固定列，消息占独立水平行
- 最小行距：带标签消息行 72 单位；紧凑仅状态行 56 单位
- 消息箭头可水平或对角；发送/接收状态在不同行时用对角箭头，不为保持水平而压扁状态行
- 状态标签放参与者生命线旁，不放消息箭头上；消息标签居中于参与者间，偏移箭头上/下 14–20 单位
- 同一 y 坐标不重复用于状态标记、消息线与消息标签；各需独立垂直槽
- 双向请求/响应对交替偏移标签或增大行距；不在中间泳道堆标签
- 跨多行的回环用不穿越节点/标签框的浅曲线；需穿越多行时预留空走廊
- 稠密协议分相为多个紧凑图或垂直堆叠面板

### 连接线规范
- `fill="none"`，用 `stroke` 而非实心填充
- 路径绕开无关节点，从不穿越
- 用直线/对角线/缓曲线/圆角 L 弯，`stroke-linejoin="round"`、`stroke-linecap="round"`
- 有向边优先标准 `marker-end` 箭头：`orient="auto"`、`markerUnits="userSpaceOnUse"`、约 `8×8`；箭头与连接线同一 path；不画为装饰曲线/括号/分离 V 形/复制的右向多边形
- 手动三角形的尖端须落目标端点，可见线接三角形底边
- 连接线标签可选；用则在连接线上/下方预留清晰胶囊，不压描带，不与任何连接线/节点/边界/图例相交
- 连接线颜色：默认 `--text-muted` 或 `--border`（中性）；主路径/焦点关系用 `--brand`；显式同辈类别用 `--chart-series-*`；语义色仅当状态/风险/健康是主编码变量

### 结构容器
- 分组容器用更大圆角矩形，内容周围有舒适内边距
- 最多 2–3 层嵌套；超出则拆分多图或用展开/折叠
- 容器边框用虚线以区别节点实线
- 图例与内嵌说明面板也是结构容器；按内容定尺寸，标记/标签/行间距与面板边界可见分离；放不下则加宽/换行/移至图下方/简化
- 图例放在主边界框外，除非边界有明确未用空间；图例与边界/连接线/模块重叠即作废

### 标签简洁
- 节点标签 2–5 词；连接线标签 1–3 词（明显关系可省略）；详细解释放回答文本

## 参考材料

| 数据关系/意图 | 参考模板 | 用法说明 |
|---|---|---|
| 模块/依赖树 | `tree-flow` | 水平节点树布局；适用于 ≤4 层依赖层级 |
| 调用链/协议时序 | `sequence-diagram` | ZenUML 风格参与者/生命线/消息布局；适用于 3-5 参与者、4-8 有序消息 |
| 模块组件与边界 | `architecture-elements` | 提供中性/brand/边界/外部块样式 + 连接线样式（中性实线、brand 虚线、中性虚线、带标签边） |
| 排期/时间线 | `gantt-chart` | 时间线 + 条形布局；适用于任务/里程碑进度 |

> 模板就绪状态以 `manifest.json` 中 `status` 为准；`planned` 时用降级原语 `node-flow` 或 `explanation-panel`。

### architecture-elements 样式参考
- **块类型**：neutral（普通模块）、brand（核心模块）、boundary（逻辑边界容器）、external（外部系统）
- **连接线类型**：neutral solid（标准调用）、brand dashed（高亮数据流）、neutral dashed（弱依赖）、labeled edge（带注解连接）

## 组合指南

1. **定方向**：信息自上而下（层级/流程）还是自左而右（时间/依赖链）
2. **选主材料**：层级 → `tree-flow`；组件架构 → `architecture-elements`；时间维度 → `gantt-chart`
3. **混搭**：可用 `architecture-elements` 块样式渲染 `tree-flow` 节点；甘特图下可附简化流程
4. **配色克制**：中性结构 + 一个 brand 焦点含义；多个同辈类别用 `--chart-series-1` 至 `--chart-series-4` 后才考虑 accent/语义色；不做彩虹层级着色
5. **图例**：超 2 种连接线样式或 2 种块样式时在预留角落或图下方加简洁图例；不浮于模块或连接线走廊上
6. **静默布局规划**：内部把每个节点、标签胶囊、徽章、图例、边界、参与者标签视为边界框；任何框会重叠或连接线会穿文字时移动/简化/转表/列表/拆分，不用非 token 微小文字、压缩间距、隐藏溢出或背景遮罩
7. **降级纪律**：自定义架构图也用降级契约；从中性容器与连接线起，加一个 brand 焦点节点/路径；仅对命名同辈类别加 chart-series 色；仅对显式状态/风险/健康编码加语义色；节点/标签/图例/面板用 token 化字体、间距、圆角
