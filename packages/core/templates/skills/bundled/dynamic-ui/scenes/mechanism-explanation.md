# Mechanism Explanation（机制解释场景）

共享契约：依次应用 `SKILL.md`、本场景文件、`templates/manifest.json`、所选 `templates/<id>/template.md`（若存在）与 `tokens/visual-tokens.md`。

## 何时进入本场景

用户意图是**理解某事物如何工作**，涉及：物理过程（热传导、电磁场、流体力学、光学、力学）、抽象机制（算法内部、协议握手、调度策略、数据管道）、因果链（事件 A 导致结果 B 的内部路径）、概念模型（注意力机制、GC 回收、锁竞争、缓存一致性）、状态演化（系统内部状态随输入/时间如何变化）。

典型触发词：原理、机制、工作原理、内部过程、under the hood、为什么发生。

**与架构场景的区别**：架构场景展示"组件间关系"；本场景展示"单一事物内部如何运作"。

## 何时拒绝

以下情况改用 Markdown 文本回答：
- 机制可在 3 句话内说清且无空间/时间维度
- 用户要代码实现而非概念解释
- 概念过于抽象无法可视化（如纯数学证明）
- 需动态仿真但 widget 环境无法支持所需复杂度

## 强制工作流

1. 确认机制有值得可视化的空间、时间、因果或状态结构
2. 识别视觉语言是物理还是抽象
3. 本场景通常无固定模板，输出前选择降级原语
4. 截面/机制用 `explanation-panel`；阶段因果链用 `node-flow`
5. 选定降级原语后再应用下方机制特定组合规则
6. 对标签、面板、标注、控件、分组区域应用 `tokens/visual-tokens.md` 的 token 化字体、间距、圆角；字面数值仅用于机制几何，不用于 UI 默认值
7. 若图形主要依赖标签，改 Markdown 或简化机制

### 核心方法论：机制优先

**画机制本身，而非"关于机制的图"**
- 错误：画一个标"哈希函数"的框，箭头指向"输出"
- 正确：画一个键被哈希映射到桶数组特定位置，展示碰撞如何用链式存储

### 物理过程 vs 抽象机制

| 类型 | 视觉语言 | 典型元素 |
|---|---|---|
| 物理 | 截面、场线、压力梯度、热流、分子交互 | token 化表面、箭头场、粒子，渐变仅用于连续变量 |
| 抽象 | 注意力矩阵、调度队列、协议时间线、管道阶段 | 网格、队列容器、时间轴、管道 |

### 组合顺序（由外而内）

1. **轮廓/边界** — 先画外形或系统边界
2. **内部结构** — 填内部组件/层
3. **输入/输出** — 标注进出路径
4. **状态指示** — 用颜色/尺寸/位置表达当前状态
5. **标签** — 最后加简洁标签

### 颜色与含义

- **暖色**（红/橙/黄）= 活跃 / 高温 / 高能 / 高频
- **冷色**（蓝/青/紫）= 静态 / 低活跃 / 低能 / 冷却
- **渐变仅用于连续变量**（温度、压力、容量、浓度）— 不用于类别区分
- 非连续类别区分用 chart-series 色或 token 系统的 brand/accent
- 背景保持中性以突出机制

### 标注规范

- 用短名词或动词短语（如"压缩"、"分配"、"回收"）
- **解释文字放回答文本** — 图中仅放定位标签
- 需编号步骤时用圈号（①②③），至多 6 步

### 动画原则

- **仅当机制有固有运动时加动画**（如旋转、流动、振荡）
- 优先 `stroke-dashoffset` 动画（流动感）或 `opacity` 脉冲（闪烁/激活）
- 避免 transform 位移动画（可能引起 widget 环境布局抖动）
- 动画须包裹在 `@media (prefers-reduced-motion: no-preference)` 中

### SVG 实践

- `viewBox="0 0 720 H"`，`width="100%"`，`height="auto"`；安全区 ≥ 40 单位
- 用 `<defs>` 定义标记与可复用元素；仅当渐变编码连续物理变量时才定义渐变
- 用 `<g>` 与语义 class/id 分组结构
- 解释方向的箭头优先紧凑 `marker-end` 箭头：`orient="auto"`、`markerUnits="userSpaceOnUse"`，与连接线同一 path；不用装饰括号曲线、分离 V 形、复制的右向三角或填充连接线做反向/左向箭头

### 机制静默预检
- 画机制本身，而非仅框与标签
- 输出前内部选物理或抽象视觉语言
- 按此顺序组合：轮廓 → 内部结构 → 输入/输出 → 状态指示 → 标签
- 颜色仅表含义：暖 = 活跃/高能，冷 = 静态/低活跃，渐变 = 连续变量
- 步骤编号 ≤6，标签简短；详细解释放回答文本
- 动画仅用于固有运动，包裹在 `prefers-reduced-motion`
- 移除装饰元素；若图形完全依赖标签才说得通，则简化或重画机制

## 组合指南

1. **识别机制类型**：物理还是抽象？决定视觉语言
2. **定关键帧**：是"静态截面"还是"过程序列"？
   - 单帧截面 → 一张 SVG 图
   - 多阶段过程 → 2–3 个并排状态帧（左→右或上→下），或带编号步骤的单图
3. **组合**：按"轮廓 → 结构 → I/O → 状态 → 标签"逐层构建
4. **配色**：默认用 token 化中性、brand、accent、语义角色；仅对物理量或连续变量选暖/冷或渐变
5. **简化**：移除无助理解的细节；若细节重要则拆为"概览 + 放大细节"
6. **验证**：若移除所有标签，图形是否仍能传达大致含义？
7. **降级纪律**：即便独特的机制草图也用中性表面、token 化含义色、token 化字体、token 化间距、token 化圆角；暖/冷或渐变例外必须编码物理连续变量，而非装饰；机制在 token 字号与间距下放不下时简化、拆分或改 Markdown，不缩小到 token 阶以下
