# Data Visualization（数据可视化场景）

共享契约：依次应用 `SKILL.md`、本场景文件、`templates/manifest.json`、所选 `templates/<id>/template.md`（若存在）与 `tokens/visual-tokens.md`。

## 何时进入本场景

用户意图涉及**表达数值关系**，包括：趋势（时序变化、增长/衰减）、对比（分组对照、排名）、构成（占比、堆叠分解）、分布（散点、密度）、相关性（多维画像、雷达）、流量（有向路径、流量分配）、强度（热力图、密度矩阵）、漏斗（转化率、阶段流失）。

典型触发词：趋势图、柱状图、饼图、漏斗图、热力图、对比图、可视化数据、chart、plot。

## 何时拒绝

以下情况改用 Markdown 文本回答，不生成可视化：
- 数据点 ≤ 2 且无对比维度（一句话即可说明）
- 用户只询问单一数值（如"xx 是多少"）
- 数据缺乏明确量化来源、完全依赖臆测
- 用户明确要求纯文本/表格输出

## 强制工作流

路由进入本场景后，必须按以下顺序执行，未完成材料审计前不得手写图表/SVG/HTML：

1. 确认内联可视化比 Markdown 更清晰
2. 从用户动词与证据需求识别主数据关系：趋势、分组对比、构成、分布、相关、流量、强度、漏斗、画像；并识别是否存在第二个证据问题（如增长来源、分段差异、流失原因、离群点、阶段总量）
3. 查阅 `templates/manifest.json` 中 `scene` 为 `data-visualization` 的条目
4. 从下方选材矩阵中筛选至多 3 个候选模板
5. 仅因具体理由否决候选：违反其避免规则、数据形状越界、所需交互不支持、模板未就绪、或 Markdown 更清晰
6. 若存在匹配主关系的就绪模板（`templates/<id>/` 下含 `template.md` + `widget-code.html` + `fixture.json`），读取 `template.md` 后从其 `widget-code.html` 与 `fixture.json` 适配；保留其降级、提示、悬停、图例与根选择器契约
7. 若提示含两个互补证据问题，合并进**一次** `pure_show_widget` 调用：先用主材料，再加至多 2 个辅助视觉，并为每个块命名其回答的问题
8. 仅当所有合理就绪模板均被具体理由否决后才生成自定义图表
9. 自定义图表输出前，选择降级原语 `chart-card`、`metric-strip-chart` 或 `compact-table-visual`，保持同一套中性表面、chart-series 配色、字体、间距、圆角、图例、降级与焦点契约

**无效的跳过模板理由**："手写更快"、"这很简单"、"自定义 SVG 更轻"、"我已经会画"。

## 选材矩阵

按意图选择，而非按松散的图表关键词：

| 数据关系/意图 | 参考模板 | 适用 | 避免 |
|---|---|---|---|
| 时序趋势 | `line-trend` | 有序时间点上的连续变化需斜率、拐点或多系列对比 | 仅单一当前值重要，或类别无序 |
| 分组量级对比 | `bar-chart-multiple` | 恰好两个同辈系列需跨同类目并排对比 | 趋势形状、堆叠贡献、精确分布或 3+ 同辈系列为主 |
| 堆叠占总比 | `bar-stacked-legend` | 各部分贡献于类别总量，总量与构成均重要 | 直接并排对比比总量更重要 |
| 带中心指标的构成 | `pie-donut-text` | 类别份额围绕一个有意义的总量或头条百分比 | 需精确排名、负值、长标签或超 5 类 |
| 标签列表占总比 | `pie-chart-label-list` | 小类别集需切片标签 + 紧凑侧标签列表 | 需精确排名、长标签、中心总量或超 5 类 |
| 相关/散点 | `scatter-chart` | 两数值维度需相关、聚类、离群或可选气泡大小 | 时序趋势、精确类别排名、日期/字符串轴或数千点 |
| 多维画像 | `radar-chart-legend` | 两个同辈来源需填充形状跨同维度集对比 | 需精确值排名、长标签或趋势为主 |
| 极简画像轮廓 | `radar-chart-lines-only` | 两同辈来源需无填充轮廓对比 | 需填充雷达、精确排名或趋势 |
| 强度/密度 | `heatmap-chart` | 值需按行/列密度、日历格或贡献强度扫描 | 需精确排名、连续趋势或多个同辈来源 |
| 漏斗/转化 | `funnel-bar-chart` | 有序阶段需流失与基线转化上下文 | 阶段为独立类别、负值重要或需装饰性漏斗体 |
| 流量/方向 | `sankey-chart` | 分阶段节点间加权流动需路径量级与节点/链路检视 | 需精确排名、循环图、双向边或稠密多对多 |

> 模板就绪状态以 `templates/manifest.json` 中 `status` 为准；`planned` 表示模板文件尚未物化，此时使用降级原语 `chart-card` 生成。

## 生成规范

### Chart.js 加载与初始化
1. 通过 UMD 加载：`<script src="https://cdn.jsdelivr.net/npm/chart.js@4"></script>`，置于 widget 底部最终 script 之前
2. canvas 须包裹在**显式高度**且 `position: relative` 的容器中
3. 实例化配置必须含 `responsive: true` 与 `maintainAspectRatio: false`
4. 默认高度 `clamp(220px, 32vw, 360px)`；最大 600px
5. 每个 widget 至多 **2 个 Chart.js canvas**；第三个辅助视觉须为 HTML/SVG（指标条、迷你条、迷你表、图例矩阵）

### 可见降级
- `<script>` 执行前保留可见的 HTML/SVG 降级（简单数据表、静态 SVG 或紧凑数据列表）
- 仅在图表创建成功后才隐藏降级（`fallbackEl.style.display = 'none'`）

### 提示框（Tooltip）
- 禁用 Chart.js 内建 canvas 提示：`plugins.tooltip.enabled = false`
- 用 `external` 处理器渲染 HTML 提示框（Shadcn 风格）
- 提示框 DOM 须位于 widget 根元素内；定位约束在图表边界内

### 动画
- 首次渲染动画 120–220ms；悬停过渡 ≤120ms

### 配色
- 系列色按序使用 `--chart-series-1` 至 `--chart-series-4`；超出 4 系列或"其他"类别用 `--chart-other`
- 同类来源用 brand chart-series 阶；4 个来源可用 `--chart-series-4` 作为唯一相邻色扩展；5+ 同辈来源须归并为 Top N + Other、拆分小多图或改用表/列表
- 自定义图表沿用就绪模板的 chart-series 顺序，不创建本地色板数组、额外 CSS 颜色变量或硬编码类别色
- 不得用 `--accent`、`--accent-2`、`--success`、`--warning`、`--danger` 表示普通同辈系列；这些 token 仅用于用户明确要求的状态/风险/健康编码
- "成功/失败/警告/阻塞/接受/拒绝"等类别标签不自动使普通对比图变为语义图，保持 `--chart-series-*` 除非图表显式为状态/风险视图
- 两系列图表须确保两色视觉上充分分离

### 根选择器
用稳定根选择器初始化：`document.querySelector('[data-dynamic-ui-widget][data-template="..."]:not([data-mounted])')`

## 组合指南

图表 widget 应保持仅图表：含图表本体、可选短标题与必要读数辅助（坐标轴/图例/标签/控件/提示）。不在图表上下方放洞察、结论、推荐或分析文案；这些放助手的周边回答中。

1. **优先单一图表**：一个模板能完整表达意图时直接用其布局 + 交互模式
2. **一个 widget 含多视觉块仅当一个图表会遮蔽第二个问题**：趋势+分解、趋势+同辈驱动、排名+分布、漏斗+分段、相关+摘要、流量+量级、热力+排期
3. **不为凑数组合**：仅当每个图表回答一个独立、可命名的问题时才用多图表
4. **多图表预算**：同一 widget 内 2-3 个视觉块；至多 2 个 Chart.js canvas，第三块须为 HTML/SVG
5. **布局**：每个大图独占整行（优先堆叠而非并排大图）；宽卡仅在大主图 + 紧凑辅助（指标卡/排名列表/迷你条/小 SVG）时用两列；窄屏堆叠主图在前辅助在后；所有视觉块共享同一网格、间距、顶对齐与图表区宽度，不做错落/瀑布流
6. **辅助卡**遵循 `tokens/visual-tokens.md` 的卡片信息层级：中性填充、token 化标题/正文/说明、辅助组至多一个 `--text-title` 数值头条
7. **不发出顺序卡片**：同一分析问题的两视觉共享标题或数据集时，合并为一个 widget 卡（共享标题、共享图例、协调间距）
8. **无 UI 分析文案**：用图表标记/标签/轴/图例/提示行为提供视觉证据，最大值、拐点、解读放回答文本
9. **图例位置**：系列 ≤3 时内联嵌入；>3 时放底部或右侧独立区
10. **数字格式**：大数用缩写（1.2K、3.4M）；百分比保留一位小数

## 数据与运行时边界

- **空数据**：不渲染空图；显示 Markdown 或可见空状态降级（标注缺失要求）
- **空值/缺失**：时序保留可见缺口；除非零语义正确，否则不静默转零；未知类别仅在来源隐含未知桶时标 `Unknown`
- **负值**：用支持负区间的柱/线；不将负值导入饼/环/漏斗/堆叠占比图
- **类别过多**：归并为 Top N + Other、小多图或紧凑表/列表；不造彩虹色板或不可读图例
- **长标签**：缩写、换行、仅模板支持时旋转，或移入提示/表文本
- **稠密点**：聚合、确定性采样、分箱为热力图，或说明紧凑内联图不适用
- **估计值**：标注为估计，精度低于实测值
- **同页多 widget**：用带 `data-template` 的稳定根选择器，绑定前设 `data-mounted="true"`，所有 DOM 查询限定在根内
- **外部库失败**：保持 HTML/SVG 降级可见且有用；仅图表创建成功后隐藏

## 输出前预检

调用 `pure_show_widget` 前静默确认：
- 所选模板 id 存在于 `manifest.json` 且属 `data-visualization` 场景；若自定义，每个合理就绪模板均有具体否决理由且明确一个降级原语驱动布局
- 图表有一个主数据关系，至多 2 个 Chart.js canvas
- 同一分析问题的互补图表在同一 widget 内，未拆成顺序调用
- 大图块未并排；仅紧凑辅助可紧邻主图
- 多块布局未错落成 2+1 行或未对齐面板
- 降级内容在 JS 运行前可见且 Chart.js 失败时仍可用
- 提示框行为保留所选模板契约，用 widget 作用域 HTML 提示
- 颜色用 `--chart-series-1` 至 `--chart-series-4` + `--chart-other`；卡片/面板表面保持中性
- 自定义输出无本地色板别名，未对普通同辈类别用 accent/语义 token
- 自定义输出用 `--font-*`、`--text-*`、`--spacer-*`、`--radius*` token 处理标题/标签/图例/提示/卡片内边距/面板间距/紧凑控件
- 未用非 token 微小文字或非 token 压缩间距强行塞入；否则简化/换行/分组/拆分或改 Markdown
- 数值标签含单位、一致舍入与必要时的估计标记
