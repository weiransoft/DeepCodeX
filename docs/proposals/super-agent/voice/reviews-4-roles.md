## 1. 架构师（评分 6.5/10，有条件通过）

### 🔴 阻断

**B1｜sidecar 生命周期与端口冲突没人负责。**
方案画了 sidecar，但全文没有回答「谁启动它、谁保证只有一个、崩了谁重启」。实际情况：

- `desktop/src-tauri/src/engine/` 已经有一套引擎子进程管理（SIGTERM → 3s → SIGKILL，见 `tray.rs` 顶部注释），sidecar 如果也走这条路要写第二份；
- CLI 版（`packages/cli`）与桌面版可以同时开，两者都读同一个 `~/.deepcode/soul/config.json`，`endpoint` 里写的 8791 会被两边抢。

要求：明确首版为**用户手动启动**，并在文档与 UI 里写死这一点；`/api/voice/status` 必须能区分「没起」与「起了但模型没加载」。**不要**在引擎启动时偷偷 spawn 一个 Python 进程——那是把 30 秒模型加载塞进启动路径。

**B2｜sidecar 无鉴权。**
`127.0.0.1` 不等于安全：同机任何进程、任何网页的 `fetch` 都能 POST 到 8791。`/tts` 可被当作免费算力刷；`/asr` 更糟——它是一个接收音频并落盘（临时文件）的接口。要求：引擎在配置里生成一个随机 `token`（`crypto.randomUUID`），sidecar 启动时读取同一配置文件并校验 `Authorization`；不匹配返回 401。

**B3｜配置与记忆同目录，但没写「谁清理」。**
`**/.deepcode/soul/` 已被 gitignore（`.gitignore:36`），`config.json` 里的 `dataUrl` 可能是用户本人照片，这条忽略规则恰好接住了。要求在文档里显式说明"头像与记忆同样不入库"，否则后续有人把 config 挪到 settings.json 就漏了。

### 🟡 建议

- `endpoint` 建议只存 host:port，协议固定 `http://`，减少一个校验维度。
- `/health` 应返回 sidecar 的 **PID 与启动时间**，多实例排查时一眼看出。

### 🟢 亮点

进程边界选得对。把 MLX 放在 Python 侧、UI 只经 HTTP，是唯一能在「模型生态在 Python」与「UI 在 WebView」之间站住的方案。

## 2. 产品经理（评分 6/10，有条件通过）

### 🔴 阻断

**B1｜语音功能默认关闭，用户要"开两次"才能用。**
`voice.enabled` 默认 `false`，装完模型还得进设置打开；再回对话页按住麦克风。第一次使用路径有三个断点（装依赖 / 开开关 / 授权麦克风）。
要求：设置页在探测到 sidecar `ready` 时给出**一键启用**（写配置 + 提示"已可用"）；未就绪时按钮直接给出安装命令，而不是灰掉不给原因。

**B2｜"试听"在改动清单里没有落点。**
方案 §4 说"有试听按钮"，§7 清单里却没有对应 API 或组件。要求：试听复用 `/api/voice/tts`（同一链路，避免"试听好听、实际不一样"），并在清单里补上。

### 🟡 建议

- 「御姐音描述」是给用户改的文本，得配 3 个预设（御姐/温柔/干练）降低空白输入的心理成本。
- 播报开关与语音总开关分两个概念，UI 上要分开写清（一个管"能不能说"，一个管"要不要自动读"）。

### 🟢 亮点

不把「语音控制桌面」塞进首版是对的。那属于意图路由，混进来会让整个链路无法验收。

## 3. 测试专家（评分 5.5/10，有条件通过）

### 🔴 阻断

**B1｜打断阈值没有数字，无法写用例。**
"RMS 连续 3 帧超阈值"里阈值是多少？帧长多少？采样率多少？三处都没写。要求：给出默认值（`RMS > 0.05`、帧 50ms、播报期阈值 ×2）并**做成可注入参数**，否则测试只能靠耳朵听。

**B2｜缺少延迟指标。**
调研报告花了整节讲 TTFA 要 < 1.5s，方案却没有一条验收标准或埋点。要求：记录每轮 `speechEnd → firstAudio` 与 `llmFirstDelta → firstAudio`，`/api/voice/status` 或前端状态里能看到最近 10 轮的数字。

**B3｜未装 sidecar 的 UI 行为没有断言。**
"明确报未就绪"是承诺，不是用例。要求断言：状态面板文案包含 `scripts/voice/setup.sh`；`SoulPane` 不出现空白区；点试听弹出错误而不是静默。

### 🟡 建议

- 空识别（<2 字）要有独立用例，别和"发送失败"混。
- 切句用例要有中文省略号「……」与英文 `...`，这两个最容易切错。

### 🟢 亮点

把"降级要显式"写成验收标准，比大多数方案只写正常路径强。

## 4. 独立开发者（评分 6/10，有条件通过）

### 🔴 阻断

**B1｜`App.tsx` 里喂句必须用 ref，不能用 state。**
`onLlmDelta`（`App.tsx:237`）每条增量都触发。若把累积文本塞进 `useState`，一次回复几十条 delta = 几十次重渲染，会明显掉帧。要求：`VoiceController` 用 `useRef` 持有，喂句是**纯副作用**，不进 React 状态。

**B2｜Composer 的麦克风必须复用现有发送路径。**
`Composer.tsx` 已有附件、@ 提及、Enter 发送等逻辑。若麦克风按钮自己调 `sendMessage`，会绕过附件与流式占位。要求：麦克风只负责"把识别结果写进输入框并触发既有发送函数"，不新建发送链路。

**B3｜`build.mjs` 的 `public` 拷贝要用递归复制。**
现有脚本 `rm -rf dist` 后逐个 `copyFile`。加 `public/` 时不能只拷一个文件，得 `cp(src, dst, {recursive:true})`，且要处理目录不存在的情况（CI 上首次构建）。

**B4｜`Info.plist` 只在打包产物生效。**
Tauri v2 的 `bundle.macOS.infoPlist` 是**打包期**合并进 `.app` 的。`tauri dev` 跑的是 `target/debug` 下的二进制，读的是自己那份默认 Info.plist——**开发态麦克风仍会被拒**。要求：文档写清"麦克风能力需 `tauri build` 后验证"，并在 UI 里把 `NotAllowedError` 翻译成"需要打包版或系统设置里授权"，别让开发者以为是代码坏了。

### 🟡 建议

- `soul-io.ts` 已有原子写，config 直接复用 `writeFileAtomic` 那套，别新写一遍。
- 切句的 Markdown 剥离用"保守白名单"：只剥离 ```代码块与行内`code`、链接 URL，其余原样——过度清洗会把正文吃掉。

### 🟢 亮点

把配置放引擎侧而不是 Tauri 私有目录，这个判断省掉了一整类"CLI 看不到"的 bug。
