# 混合内容 × 长度语音一致性验收报告

- 日期：2026-11-07
- 环境：本机 sidecar `127.0.0.1:8791`，`qwen3-customvoice` / `sinan` / `speed=1.2`，MLX 0.32.4
- 采集：`scripts/voice/mixed_matrix_probe.py`，25 格 / 179 个前端块 / **796.88 秒音频**，另有 5 格 A/B 对照 / 25 块 / 123.88 秒
- 原始报告：`/tmp/dcx-voice-matrix-final/report.json`（逐块指标）、`report.md`（自动表格）；A/B：`/tmp/dcx-matrix-norm/`

> **结论先行**：长度维度的一致性达标，音色一致性达标；内容类型维度里「符号/代码」与「数字密集」不达标。25 格门禁如实 **FAIL 15 项**，这是新增覆盖发现的历史边界，不是上一轮 `b58a9333` 的回归。根因经 ASR + A/B 真机坐实为**文本前端未做口语化规范化（TNS）**，不是语速伺服或音色参数问题。

## 1. 矩阵设计（控制变量）

| 维度 | 取值 |
|---|---|
| 长度档 | 极短 `xs`(12~26字) / 短 `s`(32~74字) / 中 `m`(60~167字) / 长 `l`(165~375字) / 超长 `xl`(398~884字) |
| 内容类型 | 纯中文 `cn` / 中英混排 `mixed` / 数字密集 `num` / 符号代码 `code` / 无标点 `plain` |
| A/B 对照 | `spoken`：与 `code` **信息量相同**、把 URL/JSON/路径/逐字母缩写改写成自然口语 |

每种内容类型有固定句子池，长度档取同一批句子的前缀或两轮重复，因此「同类型、不同长度」只差长度，「同长度、不同类型」只差字符构成。`xl` 是同批句子整轮重复两遍，额外用来量「念到后半程会不会越读越快 / 换个人」。

复刻真实前端链路：`SentenceStream + SpeechQueue` 分块（首块 14 字、后续 48 字、非首块 ≥10 等效发音单元），逐块请求 `/tts/stream`；播放侧按 `continuous` 排程（块间 gap=0、采样点硬拼接）。

## 2. 指标口径

| 类别 | 指标 |
|---|---|
| 流畅性 | 块内最长静音 / 异常长静音数、块间机械静音（前块尾 + 后块首）、局部 P95 边界跳变、逐字可逆、串行模型欠流估计 |
| 速度 | 真流式首片 TTFA（边读边计时）、每片到达时刻、逐块合成总耗时、音频总时长、RTF、整段一次请求对照 |
| 语速 | 等效发音单元/秒的块间极差、与全局固定基准 `4.1×speed=4.92` 的偏差、跨语料/跨长度/跨内容极差 |
| 音色 | F0 / 频谱质心块间极差、2 秒时间窗 F0 起伏、跨语料 F0 极差、同文本重复 3 次的 PCM 逐位一致性与 F0 稳定性 |

两个不粉饰的处理：

- **单块语料没有块间极差**，`spread()` 返回 0 不算通过。报告标 `N/A`，门禁改判「与 4.92 基准的偏差 ≤20%」和「与全局 F0 中位数的偏差 ≤20%」。
- **流式链路的边界跳变恒为 0、无区分度**：模型每块首尾自带机械静音（句首约 88ms、句尾 46~49ms），硬接缝落在静音里。硬判据换成块间机械静音 ≤200ms（由 playout.ts 已记录的 137ms 先验给 1.45 倍余量），边界跳变只留作参考。

阈值是先验值，不按本次结果倒推，见 `scripts/voice/mixed-matrix-thresholds.json`。

## 3. 四个维度的结论

| 维度 | 结论 | 关键实测 |
|---|---|---|
| **流畅性** | ✅ 基本达标 / ⏳ 符号类有静音堆积 | 异常长静音 **0**，最长块内静音 760ms（≤900ms），块间机械静音最大 106ms（≤200ms）；RTF 最大 0.40，串行保守模型下 6 格出现欠流；`code:m` 一个块 6.66s 里只有 4.08s 有声 |
| **速度** | ⏳ 未达标 | 首片 TTFA P95 **1877ms**（阈值 1500），最差 `plain:xl` **2268ms**（阈值 2000）；无标点长块普遍 1390~1878ms。`RTF` 全部 ≤0.40，合成能跟上播放 |
| **语速** | ✅ 长度无关 / ❌ 内容相关 | 长度组间语速极差 **4.72%**（≤10%）；超长档前后半同文本语速漂移 ≤**3.29%**；内容组间 **22.12%**（阈值 12%），跨语料 **25.52%**（阈值 12%） |
| **音色** | ✅ 达标 | 跨语料 F0 极差 **21.25%**（≤25%），长度组间 F0 **6.37%**，内容组间 F0 **10.80%**；同文本重复 3 次 **PCM 逐位完全一致**、F0 极差 0.00% |

按内容类型看，问题高度集中：

| 内容 | 中位语速 u/s | 组内块间语速极差 |
|---|---:|---:|
| 纯中文 | 4.93 | 4.71% |
| 中英混排 | 4.92 | 0.67% |
| 无标点 | 4.93 | 0.61% |

## 5. 根因：不是伺服，是文本前端

### 5.1 ASR 回听证据

把 `code:m` 的离群块音频送回 `/asr`，看模型实际念了什么：

| 原文 | 折算单元 | 音频 | ASR 转录 |
|---|---:|---:|---|
| `入口是 GET /api/voice/health，` | 10.7 | 2.18s | 入口是 get API voice health。 |
| `返回 {ok: true, model: {asr, tts}}，超时设成 3000ms 就够。` | 19.0 | **6.66s** | 返回 OK，True Model **S R T E S**，超时设成**三千米秒**就够。 |
| `POST https://127.0.0.1:` | 12.3 | **5.54s** | **Post HTTPs.** |
| `8791/tts/stream 的 body 是 {text,` | 11.7 | 3.12s | **八七九一十一** TTS，**STMA** 的 body 是 text。 |

`{asr, tts}` 被逐字母念、`3000ms` 被念成「三千米秒」、URL/IP 只念出「HTTPs」却拖了 5.54 秒、`stream` 含混成「STMA」。`speech_units()` 按「拉丁串 2.8 字母折 1」折算，逐字母念法的发音量被系统性低估，伺服倍率因此撞到 `TTS_RATE_SPEED_MAX=1.65` 上限，输出仍偏长；同时模型在这类文本上会产生句内静音堆积。

**提高倍率上限或改折算系数都只是让指标好看**：音频已经生成成这样，加速到 2.2 倍既超出听书舒适范围，也修不掉含混发音和静音。

### 5.2 A/B：口语化改写后立刻达标

`spoken` 语料与 `code` 信息量相同（发音单元 65.8 vs 55.0 / 171.0 vs 150.0 / 392.9 vs 364.0），只是把 URL、JSON、路径、版本号写成自然中文：

| 长度 | `code` 语速极差 | `spoken` 语速极差 | `code` TTFA | `spoken` TTFA | `code` RTF | `spoken` RTF |
|---|---:|---:|---:|---:|---:|---:|
| 极短 | N/A（偏差 23.2%） | N/A（偏差 0.4%） | 913ms | 476ms | 0.33 | 0.20 |
| 短 | 53.31% | **0.24%** | 645ms | 519ms | 0.31 | 0.17 |
| 中 | 72.48% | **0.12%** | 669ms | 522ms | 0.38 | 0.19 |
| 长 | 64.69% | **0.43%** | 738ms | 524ms | 0.35 | 0.21 |
| 超长 | 65.53% | **1.16%** | 739ms | 516ms | 0.40 | 0.20 |

\* `s` 档只有 2 块，53.31% 是 `spread()` 的参考值；门禁对它走「与基准偏差」的 N/A 替代判据（`code:s` 21.1% 超标、`spoken:s` 0.5% 达标），不把两块的极差当正式判据。

`spoken` 五格中位语速 4.93~4.94 u/s，跨语料语速极差 **0.26%**、F0 极差 7.30%、TTFA P95 **524ms**、异常长静音 0。分块数也从 26 降到 14（少独立生成 = 少起头语调漂移）。

## 6. 建议的下一步（未实施，需你确认）

1. **文本前端规范化（TNS），默认关闭、可一键回退**：在送 TTS 前把 URL / JSON / 路径 / 逐字母缩写 / 版本号改写成口语中文，开关形如 `DCX_VOICE_TNS=0`；先做 A/B 灰度，再决定是否默认开。这也顺带覆盖待办「陪伴模式回复简短且不逐字念全文」。
2. **无标点长文本的 TTFA**：`plain` 档首片 1390~2268ms，其余档 476~1378ms。可评估更小的 `streaming_interval` 或在前端把首块切得更短；改前需真机复测，不能只按指标调参。
3. **不要把符号类语料从门禁里删掉**：保留 25 格完整矩阵作为压力基线，日常回归可另设 `--cells` 子集，但违规项必须持续可见。

## 8. 诚实边界

- 量的是本机 sidecar 的**客观音频/时序指标**；F0 与频谱质心只是音色代理，不等于说话人验证，也不等于桌面 WebView 真机听感。纯拉丁复合词块 1.61 倍保调变速后是否显得赶，仍需你本人确认。
- RTF 与欠流用「逐块串行」保守模型，前端 SpeechQueue 会提前预取，实际断流风险不高于本文数值。
- `l` / `xl` 档不做整段一次请求对照（那一层由 `longtext_probe.py` 覆盖）。
- A/B 的 `spoken` 语料是**人工改写**的固定样本，证明的是「规范化方向有效」，不等于已经实现或验证了通用 TNS 规则。
- 固定 speaker 压得住块间语速与 F0，但多次独立自回归生成的起头语调仍带来时间窗 F0 起伏；彻底跨段音色克隆需换 base 模型权重，本轮及上一轮均未做。
