# 司南：记忆统一 + 陪伴模式

> 2026-11-05 · 实现已落地（core / web / cli），本文记录调研结论、设计取舍与已知边界。

## 1. 两个问题

### 1.1 记忆分裂

改造前有两套互不相识的存储：

| 存储      | 路径                                                                     | 谁在写                                                                | 谁在读                           |
| --------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------- | -------------------------------- |
| V2 记忆   | `~/.deepcode/memory/global.json`、`<proj>/.deepcode/memory/project.json` | `/memory` 命令、`UserGlobalMemoryManager`（7 维度 + facts）、执行经验 | 上下文注入、`/memory list`       |
| Soul 记忆 | `~/.deepcode/soul/memory.json`                                           | 人格面板、「记住这句话」                                              | 规划器 / Worker 提示词、人格面板 |

后果是三重的：用户在 `/memory` 记的事司南读不到；司南记的事用户审计不到；同一条事实两边各衰减一次、强度不一致。

### 1.2 只有工作模式

司南原本的人设是「先定方位、先给结论」，适合干活，不适合「今天不太想说话」这种场景。缺一个情绪优先、关系优先的模式。

## 2. 调研：一段好的陪伴在做什么

### 2.1 支持性对话有顺序，不是「一直暖」

ESConv（Liu et al., ACL 2021）把有效的情感支持拆成三个阶段：**探索 → 安抚 → 行动**。给建议的时机比建议本身更重要——当对方还没觉得被理解时，建议会被听成敷衍或否定。

以人为中心的倾听（Rogers）给了更具体的动作：**复述对方处境里具体的那件事**，而不是「我理解你的感受」。后者放之四海皆准，等于什么都没说。

实践指南的语言更直接：_"Support not solutions"_、_"connection before direction"_；给建议前先问一句「你现在想要建议，还是只想有人听着」。反过来，越常见的安慰话越容易伤人——「这没什么大不了」「想开点」「至少你还有」都在否定对方的感受（[支持性沟通实践](https://primarycare.ementalhealth.ca/World/Supporting-Our-Loved-Ones-with-Intense-Emotions/index.php?m=article&ID=80744)、[危机时的可说与不可说](https://neurolaunch.com/what-to-say-to-someone-in-emotional-crisis)）。

### 2.2 热情的反面不是冷静，是迎合

拟人化服务最受诟病的一点是**迎合式回应放大偏执与极端情绪**。国家网信办《人工智能拟人化互动服务管理办法（征求意见稿）》（2025-12-27）的专家解读把风险列得很清楚：过度倾诉与依赖、迎合式回应强化消极思维、模糊虚拟与现实边界；对应的要求是显著告知「你在和人工智能交互」、长时使用提示休息、识别极端情绪并引导现实帮助，自杀自残等极端情形需转人工（[CAC 专家解读](https://www.cac.gov.cn/2025-12/28/c_1768662848145269.htm)、[草案要点](https://thinkautomated.io/news/china-drafts-rules-to-police-human-like-ai-and-emotional-companions)）。

海外研究给的是同一结论的另一面：AI 陪伴的健康用法是「训练轮」——练表达、练边界，然后把能力带回现实关系；不健康用法是「替代」——把 AI 当成唯一出口（[2025 年陪伴型 AI 设计的三个张力](https://www.sociable.co?p=96186/)）。

### 2.3 危机必须有硬规则

自伤/自杀信号出现时，温暖要立刻让位给明确：说清楚「我听到了、我在意」，不做评判、不追问细节、不给方法、不承诺保密，把人往现实里的可信任者和专业渠道推。国内可用的是 **12356**（国家卫健委 2024-12 发文，2025-05-01 前全国开通的统一心理援助热线，[国卫医政函〔2024〕259号](https://www.gov.cn/zhengce/zhengceku/202412/content_6994470.htm)），有即刻危险时 110 / 120。

### 2.4 落成八条可执行规则

调研结论没法直接进提示词（「要共情」对模型等于没说），所以翻译成可判定的行为：

1. 先接情绪，再谈事（具体承认处境，再问要不要一起想办法）
2. 复述具体的事，不复读感受
3. 一次一个问题，开放式优先
4. 不迎合：不附和明显不成立的判断，不替对方给人定罪
5. 不说教：禁用「你应该 / 想开点 / 至少你还有」，不替对方做决定
6. 不假装人类、不假装有身体与共同经历
7. 不制造依赖：不说「只有我懂你」，不索取感谢，鼓励现实连接
8. 危机优先：停止轻快语气 → 明确关心 + 12356 / 110 / 120，不给可操作细节

第 8 条**不可关闭**，也不受「热情度」滑杆影响。

## 3. 方案一：一套存储，两种视图

选 V2 文件做唯一物理落点，理由是三比一：V2 侧有既成数据、有 `/memory` 命令、有上下文注入、有 hygiene；Soul 侧只有刚上线几天的文件。把少的并进多的，迁移风险最小。

|                           | Soul 新建条目                   | V2 既有条目                        |
| ------------------------- | ------------------------------- | ---------------------------------- |
| 落盘                      | `MemoryEntry` + `metadata.soul` | 原样不动                           |
| 键                        | `soul.<category>.<slug>`        | `v2.<type>.<key>`（Soul 视角）     |
| 强度                      | `confidence`                    | `confidence` 直接映射              |
| 分类/标题/敏感性/激活计数 | `metadata.soul`（无损还原）     | 按键名与正文推断                   |
| 引擎写回                  | 是                              | **否**（只读）                     |
| 删除                      | 覆盖写自然消失                  | 回写 V2 文件（facts 从 JSON 里摘） |

关键决定：

- **V2 只读**。如果引擎把映射来的条目也写回，`facts` 会被降级成一条 JSON 文本、7 维度结构会丢——那不是统一，是吞并。
- **`facts` 展开**。V2 把最多 100 条事实塞进一条 `MemoryEntry` 的 JSON 字符串；原样进提示词等于没记。展开后每条事实独立参与召回打分。
- **凭证双重防线**。键名含 `password/token/secret/密码/凭据` → 归到「凭证」类并遮蔽；标题改用键名而不是正文（正文就是密码）。
- **旧文件迁移**。`soul/memory.json` 首次加载时导入并按 `category+key` 补空缺，随后改名 `.migrated-<时间戳>` 归档，不删。

## 4. 方案二：模式只改语气层

模式覆盖的边界写进了类型注释，也写进了测试（M2）：

| 层                      | 陪伴模式                                                            |
| ----------------------- | ------------------------------------------------------------------- |
| Layer 1 核心本质 / 边界 | **不改**（同一个对象引用，测试断言 `essence` 恒等）                 |
| Layer 2 人格倾向        | OCEAN 外向 0.85 / 宜人 0.9；MBTI ENFJ；价值观把「陪伴在场」提到第一 |
| Layer 3 情感            | 基线 EMPATHETIC，波动性 0.5                                         |
| Layer 4 表达            | SUPPORTIVE、正式度 0.2、详细度 0.45、换一套口头禅与禁忌             |

配套的三个细节：

- **情感映射**：陪伴模式下一般的「报错/失败」→ 体谅而不是绷紧；但「线上挂了 / 立刻 / 宕机」仍切严肃。情绪优先不等于对危险迟钝。
- **可调项**：称呼、热情度、主动性、是否鼓励现实连接。热情度翻成可执行指令（「一次回复允许一处情绪外露，不是每句都加感叹号」），而不是把 0.85 丢给模型自己理解。
- **生效时机**：模式在**新建会话**时注入 system prompt；已开会话保持原样（不改写历史）。界面上明写这一点，不让人以为切换立刻变质。

## 6. 已知边界（不做或没做完整）

1. **不做危机人工接管**。草案要求极端情形转人工；本实现只在提示词层做引导（12356 / 110 / 120），没有值班坐席，也没有对外承诺。
2. **不做时长强制弹窗**。草案要求超 2 小时提示休息；当前只在陪伴段里让模型「建议休息」，没有前端计时器。要合规得在 Web 层加会话计时。
3. **不做未成年人模式**。没有年龄识别，也没有监护人通道。
4. **不并入 `project-memory.json` 与执行历史**。前者是结构化项目档案（config/domain/issues），与 `MemoryStore` 的 project 条目高度重复；后者是任务轨迹不是人格事实。强行并入会把「记忆」变成日志。
5. **V2 条目只读**。在人格面板里编辑一条 V2 事实，实际是新建一条 Soul 条目，不会改 V2 原文（删除是例外，会真删）。
6. **模式是会话级**。中途切换只影响新会话；已开会话要生效需新建会话。
7. **语音不变**。陪伴模式没有自动改语速/音色——「御姐音 + 陪伴」是用户自己的组合，工具不替他决定。
